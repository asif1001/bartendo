# ASIF RGB CONTROLLER

Cross-platform Bluetooth (BLE) RGB LED controller for the **ESP32-S3 WROOM**
— a React + Capacitor Progressive Web App that runs as a **website, native
Android app, and native iPhone app**, controlling the onboard WS2812 LED
(GPIO 48).

| Layer | Choice |
|---|---|
| UI | React 19 + TypeScript + Tailwind CSS v4 (mobile-first, dark theme) |
| Icons | lucide-react |
| Build | Vite 7 |
| PWA | vite-plugin-pwa (installable, offline shell) |
| Native shells | Capacitor 8 (`com.asif.rgbcontroller`) |
| BLE (native apps) | [`@capacitor-community/bluetooth-le`](https://github.com/capacitor-community/bluetooth-le) v8 — peer-compatible with Capacitor 8 (verified) |
| BLE (desktop web) | Web Bluetooth (`navigator.bluetooth`) |
| Firmware | ESP32 BLE (Bluedroid) + Adafruit NeoPixel |

> **iPhone note:** iOS Safari does **not** support Web Bluetooth. iPhone users
> must install the Capacitor iOS app (§9). Web Bluetooth is only used on
> Chrome/Edge and Android Chrome.

## 1. Project Overview

```
Phone (web PWA / Android / iOS)
   └── BLE write (UTF-8 text): "RGB:255,0,0"
        └── ESP32-S3 : Asif_ESP32_RGB  (GPIO 48, WS2812 onboard LED)
```

Screens: Dashboard (scan/connect), Colors, Brightness, Power, Device Info,
Settings. All controls transmit real `ON` / `OFF` / `RGB:r,g,b` /
`BRIGHTNESS:0-100` commands; there is no simulated BLE anywhere in production
code — every write goes through the GATT characteristic.

## 2. Hardware Requirements

- **ESP32-S3 DevKit (WROOM)** with onboard addressable RGB LED
- LED GPIO **48** (WS2812/NeoPixel-compatible, one pixel)
- USB data cable for flashing
- Works out of the box with the provided firmware — no wiring needed

Optional: strip of WS2812 LEDs — set `LED_COUNT` in the firmware.

## 3. ESP32 Firmware Installation

   (Board Manager → install *"esp32 by Espressif Systems"*, v3.x)

## 5. Bluetooth UUID Configuration

| Item | Value |
|---|---|
| Device name | `Asif_ESP32_RGB` |
| Service UUID | `12345678-1234-1234-1234-123456789001` |
| Characteristic UUID | `12345678-1234-1234-1234-123456789002` |
| Properties | READ + WRITE, UTF-8 text |

These live in exactly two places that must stay in sync:
`firmware/Asif_ESP32_RGB_Controller.ino` and
`src/services/bluetooth/BLEConstants.ts`. See `docs/BLE_PROTOCOL.md` for the
full protocol grammar and what firmware changes any deviation would require.

## 6. How BLE Communication Works

1. The app **scans** (or opens the browser picker on desktop web), filtering
   by name prefix `Asif_ESP32_RGB` / service UUID.
2. On connect the stack performs **GATT service discovery** and verifies the
   characteristic exists and is writable — the UI only shows *Connected*
   after that succeeds.
3. Commands are **queued** (`BluetoothManager.sendCommand`): writes are
   strictly serial, paced ≥ 150 ms apart, and the colour/brightness sliders
   debounce (180/250 ms) so a drag never floods the characteristic.
4. Unexpected disconnects trigger the disconnect state, and with *Auto
   reconnect* enabled the backoff retries are 2 s → 5 s → 10 s
   (native transports only; the browser requires re-picking the device).
5. The characteristic is also **READ**-able: the firmware answers with
   `ON|RGB:255,0,0|BRIGHTNESS:50`, which the native transport uses to verify
   discovery before allowing commands.

## 7. Web App Installation & Local Development

```bash
git clone https://github.com/asif1001/bartendo.git
cd bartendo
npm ci
npm run icons      # generates public/icons/icon-{192,512}.png
npm run dev        # http://localhost:5173 --host exposes the LAN
```

To verify against real hardware locally you need an HTTPS/secure context:
use `npx localtunnel --port 5173` (or Chrome on Android pointing at the dev
server) — Web Bluetooth is not available over plain HTTP on a phone.

## 8. Building the Android App

One-time prerequisites: **JDK 21**, **Android Studio** (SDK 34+).

```bash
npm run build
npx cap add android     # first time only — generates android/
npx cap sync            # after every web build
npx cap open android    # build/run in Android Studio
```

Debug APK install:

```bash
cd android
./gradlew assembleDebug
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

Signing for Play Store: *Build → Generate Signed Bundle/APK*, use your own
keystore. Permissions required (mostly staged by the plugin; verify in
`android/app/src/main/AndroidManifest.xml`):

```xml
<uses-permission android:name="android.permission.BLUETOOTH_SCAN"
    android:usesPermissionFlags="neverForLocation" />
<uses-permission android:name="android.permission.BLUETOOTH_CONNECT" />
<uses-permission android:name="android.permission.ACCESS_FINE_LOCATION"
    android:maxSdkVersion="30" />
<uses-permission android:name="android.permission.BLUETOOTH"
    android:maxSdkVersion="30" />
<uses-permission android:name="android.permission.BLUETOOTH_ADMIN"
    android:maxSdkVersion="30" />
```

Runtime prompts are handled by `BleClient.requestPermissions()` on first scan
(Android 12+; location on older Android automatically).

## 9. Building the iPhone App (requires macOS + Xcode)

```bash
npm run build
npx cap add ios      # first time only — generates ios/
npx cap sync
npx cap open ios     # opens Xcode
```

In Xcode:

1. Select the **App** target → *Signing & Capabilities* → choose your team
   (free Apple ID works for personal-device installs).
2. Ensure `Info.plist` contains the Bluetooth usage descriptions:

```xml
<key>NSBluetoothAlwaysUsageDescription</key>
<string>Asif RGB Controller uses Bluetooth to connect to your ESP32 RGB LED.</string>
```

3. Connect the iPhone, trust the developer certificate on the device
   (*Settings → General → VPN & Device Management*), press **Run**.

Grid deployment to TestFlight/App Store requires a paid Apple Developer
account. iOS cannot be built or signed on Windows — that is an Apple
toolchain limitation, not an app limitation.

## 11. Troubleshooting

| Symptom | Cause & fix |
|---|---|
| "Bluetooth unavailable" on desktop | Browser lacks Web Bluetooth. Use Chrome/Edge, or the mobile app. |
| "Bluetooth is turned off" | Enable BT in system settings, then re-scan. |
| Scan finds nothing | ESP32 must be powered. On native, name filter is `Asif_ESP32_RGB` — check the advert name in a tool like *nRF Connect*. |
| Factory chooser is empty (web) | The firmware must advertise the service UUID (`addServiceUUID` in the .ino) for the filter `{ services: [...] }` and name matching. |
| Connection times out | ESP32 in use by another central (BLE allows one connection here)? Disconnect other apps/phones and retry. |
| Service not found | Earlier firmware revision with different UUIDs — reflash §3, verify §5. |
| Writes silently fail | Another phone may hold the GATT link; BLE write also fails pre- Android-pairing when `BLUETOOTH_CONNECT` is missing — reinstall the app and accept the permission. |
| iPhone can't use web Bluetooth | By design: iOS Safari has no Web Bluetooth. Install the Capacitor iOS app (§9). |
| Reconnect button does nothing (web) | Browsers forget granted devices in private mode / after clearing cookies — re-scan instead. |
| LED stays white/bright on boot only | `LED_PIN = 48` target: some S3 boards wire the onboard LED on other pins — adjust `LED_PIN` only, never the UUIDs. |
